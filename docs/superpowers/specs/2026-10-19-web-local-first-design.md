# 代肝记录网页端：本地优先架构设计

日期：2026-10-19。状态：用户已审阅确认，授权编写实施计划；尚未进入实现。

## 1. 已确认的目标与边界

为个人游戏代肝接单者提供电脑、手机浏览器均可使用的本地账本，保留现有奶油白、鼠尾草绿与手账风格。第一版无需注册，无业务云端服务，两端分别保存资料，通过通用 `.dgbk` 备份文件手动接续使用。

用户已确认：网页第一版完整覆盖安卓业务闭环；后台定时通知留待后续。覆盖老板、账号、托管和短期订单、续期、日期纠错、作废与空单清理、任务及打卡、截图、批量完成及撤销、收款更正与统计、模板、归档、备份恢复。

手动导入为整份替换，不合并两个设备分别编辑的资料。云端备份与恢复是后续阶段；自动同步与冲突合并另行设计。网站发布、自动化部署与业务实现不包含在本次设计交付中。

成功标准：用户能从安卓导出资料，在网页完成日常工作，再导出回安卓；业务含义、历史和附件不丢失，失败恢复不破坏原资料。

## 2. 方案比较与选择

| 方案 | 优点 | 当前代价 | 决策 |
|---|---|---|---|
| React + Dexie / IndexedDB | 本地优先，无业务服务器，适合响应式界面和截图 Blob | 关系约束需要业务层实现，浏览器存储需备份 | 采用 |
| 浏览器 SQLite / WASM | 与安卓 SQL 模型较近 | Worker、文件持久化与浏览器适配面更大 | 当前不采用 |
| React + 云端数据库/API | 便于集中存储和跨设备访问 | 引入账号、运维与上传数据，偏离已确认范围 | 后续按需要设计 |

网页作为静态站点运行，业务数据不发往站点服务器。使用 React、TypeScript、Vite；Dexie 保存业务与截图；shadcn/ui 作为可定制组件基础；PWA 缓存应用资源。依赖确切版本在实施准备时核验并锁定，不凭本设计指定未经验证的组合。

参考上游：
- https://github.com/dexie/Dexie.js
- https://github.com/shadcn-ui/ui
- https://github.com/vite-pwa/vite-plugin-pwa

## 3. 页面与交互

### 导航与布局

主导航：今日事项、老板与账号、订单、收款与统计、模板库、资料与设置。桌面使用侧边导航，宽屏老板/订单列表与详情并排；手机保留今日事项、老板、订单、更多四个底部入口，更多收纳其他功能。窄屏详情独立显示，返回保留筛选及滚动位置。

布局依容器空间切换，内容不依赖固定设备型号。主要触控目标至少 44px，表单有明确标签与键盘焦点；金额与状态同时使用文字，不仅依赖颜色。弹窗和侧栏有焦点管理，手机软键盘出现后仍可完成提交。

### 业务页面

| 页面 | 核心内容和操作 |
|---|---|
| 首次使用 | 新建空账本 / 导入安卓或网页备份；说明资料保存在当前浏览器 |
| 今日事项 | 游戏/账号筛选、托管和短期任务、完成/补录、截图、批量完成与撤销 |
| 老板与账号 | 搜索、老板详情、账号登录资料、订单关联、归档与恢复；归档区默认收起 |
| 订单 | 状态和类型筛选、新建订单、任务进度、打卡日历、期次、续期、日期纠错与管理 |
| 收款与统计 | 实收流水、待收款、按期次收款、更正/作废历史、月份与报表时区 |
| 模板库 | 内置/自定义模板、分类任务、周期配置、单模板导入导出 |
| 资料与设置 | 完整备份/恢复、备份记录、存储状态、主题、报表时区、网页提醒说明 |

新建订单分为选择老板/账号、服务与任务、价格与首笔收款三个逻辑步骤，桌面可同页分区。只在数据库事务完成后显示“已保存”；失败保留输入并提供重试。敏感账号密码默认遮挡，用户主动查看或复制，不写入全局搜索结果、日志和通知。

网页内根据当前业务状态显示任务、到期与欠款提示。安卓的三类提醒开关与时间保留为可往返的数据，在网页只读展示并说明适用平台；不申请浏览器通知权限，不承诺关页后的定时通知。日期提示在前台计时、重新聚焦和业务更新后重新计算。

## 4. 模块与代码边界

建议在现有仓库新增 `web/`，独立管理网页构建，保持安卓构建入口。实现时先读取该目录适用的仓库指引。

| 模块 | 单一职责 |
|---|---|
| app / features | 导航、页面、表单、交互状态；调用业务服务 |
| domain | 金额、游戏日历、周期发生槽、状态与账目规则；不依赖 React 或 Dexie |
| application | 建单、收款、更正、续期、归档、批量完成/撤销等命令与事务边界 |
| storage | Dexie 表、索引、事务、活动资料身份、浏览器内部迁移 |
| backup | 标准格式读写、密码信封、输入限制、校验、预览和整体替换 |
| platform | 文件选择/下载、存储容量、应用缓存和更新协调 |

页面不直接写表。应用层以数据访问接口隔离存储，每个业务命令在单个 IndexedDB 事务中检查归属、状态和约束后提交。可等待的文件解析、加密和其他非数据库工作在事务外完成，避免数据库事务提前失效。

不将现有 Kotlin 界面或 Room DAO 编译到网页；移植业务语义并复用中立测试夹具。暂不引入微服务、自建同步引擎或为未来同步增加空壳接口。

## 5. 数据模型与业务一致性

安卓业务事实以当前 schema 8、实体、仓储实现和测试为准。`docs/data-model.md` 部分版本叙述仍停留在 schema 7，不能据此删除 schema 8 的作废及月号字段。

网页内部可增加本机协调表和附件 Blob 表；标准业务表字段通过显式适配器映射，不把 Dexie 内部结构直接导出。数据库内部版本与备份协议版本独立。

- 保留业务 UUID、操作 ID、原时间、精确小数文本、模板和游戏日历快照。
- 金额使用安全整数分；解析整数时检查安全范围，禁止浮点金额或无损性未知的类型转换。
- 实际时刻使用 epoch 毫秒；游戏日期保留 ISO 日期字符串，不经过设备时区隐式转换。
- 时区、日/周刷新和周期语义与安卓一致；每月指定日遇到不存在的日期跳过，不挪到月末。
- 任务发生槽保持稳定键及唯一约束，重复点击不生成重复打卡。
- 建单、收款、更正、续期和批量完成使用现有幂等语义；相同操作不同载荷拒绝。
- 收款依据 ACTIVE 流水计算，更正保留原行与审计；续期不重写旧期价格和欠款。
- 作废保留历史和实际收入，并按安卓 v1.6 规则退出任务、待收与有效接单计数。
- 删除空单、归档守卫、恢复归档批次、日期纠错和批量撤销冲突判断与安卓一致。
- IndexedDB 没有 SQL 外键自动保障；业务写入及导入校验器显式检查外键、唯一性与跨表归属。

截图元数据与 Blob 一起存在当前资料数据库，新增/替换/删除在同一事务提交，避免数据库和文件系统的跨资源切换问题。附件路径与原文件字节通过备份适配器保持兼容，不自动压缩或重编码已有截图。

## 6. 备份协议与兼容矩阵

协议以 `docs/backup-format.md` 及安卓 `backup/` 实现为依据：`.dgbk`、`daigan-backup` v1、`manifest.json`、`data.json` 和 `attachments/`；18 张业务表，明确列顺序、类型、数量和 SHA-256。

| 输入/输出 | 网页第一版行为 |
|---|---|
| schema 8 普通或加密备份 | 接受并完整验证 |
| schema 7 普通或加密备份 | 按现有 7→8 规则补三个 NULL 列，再验证 |
| 未知协议、加密信封或 schema | 替换前拒绝，不尝试猜测格式 |
| 网页导出 | 格式 v1、schema 8，可由安卓 v1.6 恢复 |
| 旧安卓版本读取 schema 8 | 不承诺兼容，导出界面说明适用版本 |

加密与安卓保持逐字节格式一致：`DAIGANBK` 信封、PBKDF2-HMAC-SHA256（210000 次）、16 字节盐、12 字节 nonce、AES-256-GCM 和 128 位标签；使用 Web Crypto 实现。密码编码、Unicode 字符、长度边界及 GCM 布局以安卓实现和跨端夹具验证，不用同语言自往返代替兼容证明。密码仅用于当前会话，不持久化；网页运行时不承诺秘密能可靠从内存擦除。

提醒设置属于通用业务备份，网页原样保留；`app_settings`、`reminder_deliveries` 以及网页的活动数据库、导入日志、主题和备份记录均不进入标准业务表目录。

继续遵守归档 512 MiB、JSON 64 MiB、清单 1 MiB、2000 个附件、单图 32 MiB、附件总计 384 MiB、5000 条目及既有解压比/深度限制。使用增量计数和限制，不信任归档声明；加密整体归档在浏览器中仍可能受到内存约束，达格式上限不等于保证所有手机可处理。导入前检查容量，资源不足明确失败并保留原资料；目标浏览器必须报告已验证的大文件边界，不能宣称覆盖未经实测的上限。

## 7. 导入、导出及中断恢复

### 导入

1. 文件选择和按需解密；密码错误或认证失败不解包、不改当前资料。
2. 限额解包，检查路径、条目、哈希、精确表列、值类型、枚举、外键、唯一性、归属及金额等业务不变量。
3. 写入新的随机命名暂存数据库，包含数据和附件；验证后标记 READY。
4. 预览来源生成器、导出时间、老板/订单/附件数量、总实收和待收，并明确“替换本机资料，不合并”。
5. 提供“先导出当前资料”（推荐）及“已另行备份，继续替换”；不将自动生成的本地副本冒充用户已保存的外部备份。
6. 取得跨标签页排他许可，关闭业务写入和导出，重新检查当前资料代次及候选状态。原资料在预览后有变化时，要求刷新预览再确认。
7. 在独立控制数据库的单一事务中，将活动数据库指针与资料代次切到 READY 候选。此指针事务为唯一提交点。
8. 通知所有页面重新打开当前资料，废弃旧表单/异步结果。确认新资料可打开后清理原数据库；清理失败可稍后重试，不回滚已提交指针。

启动先读取控制数据库。提交前中断继续使用旧资料，提交后使用新资料。未激活的暂存数据库仅在持有维护锁时按会话状态清理，不能误删正在准备的导入；活动数据库不存在或不完整时保留现场并提供恢复入口，不自动新建空账本覆盖状态。

### 导出

取得跨标签页排他许可，读取当前完整数据与附件引用形成一致快照；快照就绪后释放许可，再在 Worker 中打包、哈希及可选加密。导出不读到跨事务混合状态。导出与导入提交互斥，提示准备中的短暂只读状态。

支持显式保存/下载文件及取消，不把文件选择器取消当成错误。浏览器只发起下载而无法确认落盘时，状态写“已生成并发起下载”，不写“备份已安全保存”。记录生成时间与资料代次，业务更新后提示“自上次导出后有修改”；这不代表已检测外部备份文件仍然存在。

## 8. 多标签页与本地存储

以同源跨标签页锁协调写入、导出和资料切换，配合消息广播刷新状态；广播只做通知，不作为正确性保障。每次操作持锁后检查活动资料代次，旧代次写入被拒绝。业务事务防止重复编号与操作键冲突。

具备可靠跨标签页锁能力的浏览器才开启写入；能力不足时给出明确的受支持浏览器提示，禁止静默退化到无保护写入。待实现验证后发布确切浏览器版本矩阵。

申请持久存储并显示请求结果，提供容量估算、备份入口及存储不足错误。隐私浏览或不可持久化环境明确提示，不保证系统清理后可恢复。网站更换域名、协议或端口会形成不同的本地资料空间，因此正式发布后保持稳定 HTTPS 来源；域名迁移通过旧站导出、新站导入完成。

## 9. 离线、更新与敏感资料

首访联网加载完成后缓存应用壳、必要字体图标及内置模板，业务页离线可用；不依赖在线字体/CDN 才能完成核心操作。账号、密码、截图不进入网络请求、URL、分析服务或 Service Worker 业务缓存，不接入第三方行为分析。

网页本地数据库不等于加密保险箱；可选备份加密仅保护导出文件，第一版不承诺本地数据库加密或应用锁。显示敏感内容使用文本渲染，禁止将导入备注当作 HTML 执行。

发现应用更新显示“更新可用”，不强制刷新。导入、导出、提交和未保存表单期间不能激活更新。数据库升级开始前协调其他标签页关闭连接，blocked 时明确提示；迁移失败保留原数据，不清库重建。界面须区分业务保存成功、下载已发起、应用更新三个状态。

## 10. 后续云端演进

备份编解码与文件选择/下载分离，后续可增加云端文件保存方式，保持本地业务无需网络。未来云备份需设计身份认证、快照版本、加密密钥和设备间覆盖提示。

稳定业务/操作 ID 和快照可复用，但当前资料身份只是本机防陈旧写入机制，不代表跨设备同步版本。自动同步需另行设计操作传播、删除语义、冲突、收款审计和附件同步，不在第一版预埋未经需求验证的同步引擎。

## 11. 验收与交付条件

以下为待执行验收，本文不宣称测试已经通过：

1. 业务规则：以安卓案例为基准验证周期、游戏刷新、时区/DST、月缺日、金额、续期、归档、作废、日期纠错、批量撤销冲突及重复提交。
2. 跨端兼容：schema 7/8；安卓→网页→安卓及网页→安卓→网页；普通和加密；中文及 Unicode 密码；登录资料、全部业务列、原始附件字节和审计记录保持一致。比较规范化业务数据和附件哈希，不要求随机盐、ZIP 时间或生成器相同。
3. 恶意/损坏文件：错误密码、篡改密文、坏哈希、重复/穿越条目、错误表列、孤儿引用、超限、过度压缩均拒绝，当前资料不变。
4. 恢复与并发：暂存中断、READY 前后、指针提交前后关闭页面并重启；容量不足；双标签页写入/导出/导入竞争；旧表单提交和清理失败，均保持完整旧或新资料。
5. 浏览器：桌面 Chromium、Firefox、Safari，以及 Android Chrome、iPhone Safari，实测基础读写、Blob、锁、Web Crypto、文件下载和离线重开；确切版本与容量边界写入发布记录。
6. 界面：手机/桌面布局、长中文、大字体、键盘导航、深浅主题、空/错误/加载状态；不横向挤压主要表单，不显示成功但实际未保存。
7. 离线与升级：首次完整加载后断网新建/打卡/收款/查看截图/导出；更新不打断编辑、导入或迁移；所有兼容范围内历史网页数据库迁移保留资料。

实施先建立备份夹具及双向兼容验证，再完成数据层和业务命令，随后接入完整页面、离线更新与浏览器验收。具体任务拆分、执行顺序、测试命令和执行方式在用户审阅此文后编写实施计划。
